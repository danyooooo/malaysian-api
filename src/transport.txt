TUJU SHARED ROUTE PAYLOAD

Used by:
  POST /tuju/highways/inroute
  POST /tuju/rsa/inroute
  POST /tuju/toll-rates
  POST /tuju/route/encode
  POST /tuju/route/resolve (location inputs only; always OSRM)

Payload: Supply one route/location representation per JSON object:
  coordinates: <array of [latitude, longitude] pairs>
  points: <array of {lat,lng}, {lat,lon}, or {latitude,longitude} objects>
  path: <ordered coordinate-pair or point-object array>
  geometry: <GeoJSON LineString or Feature containing a LineString>
  route: <selected map route, or Google/OSRM response containing routes>
  encoded_polyline: <precision-5 encoded polyline string>
  origin + destination: <coordinate objects/pairs> (required together if used)
  from + to: <aliases for origin + destination>
  waypoints: <intermediate location array with origin/destination, or standalone
              ordered location array for OSRM resolution>

Optional payload controls:
  coordinate_order: [latlng, lnglat] (default: latlng for non-GeoJSON arrays)
  geometry_format: [polyline, polyline6, geojson] (default: polyline; declare
                    polyline6 for precision 6 strings)
  geometries: <alias for geometry_format>
  route_index: <nonnegative integer> (default: 0; selected alternative;
                OSRM resolution accepts 0-3)
  resolver: [osrm, none] (osrm resolves locations; none keeps a supplied path local)
  osrm: <object> (routing options below)

Coordinate behavior:
  WGS84 geographic coordinates; latitude -90..90, longitude -180..180.
  GeoJSON is always [longitude, latitude]. Other arrays default to [lat, lng].
  Send ordered road-path points for local conversion; at least two required.
  Origin/destination inputs automatically invoke OSRM with optional waypoints.
  Add resolver=osrm to route coordinates/points/path as locations to visit.
  For standalone waypoints, add resolver=osrm or use /tuju/route/resolve.
  Do not combine precomputed map geometry with an OSRM location request.
  Addresses and place IDs must first be converted to coordinates by the client.
  Supported Google route data includes overview_path, overview_polyline,
    polyline.encodedPolyline, and polyline.geoJsonLinestring.
  A GeoJSON LineString/Feature may also be the complete body itself.

Payload examples:
  {"coordinates":[[3.233,101.581],[3.223395,101.577242],[3.213,101.571]]}
  {"coordinate_order":"lnglat","coordinates":[[101.581,3.233],[101.577242,3.223395]]}
  {"geometry":{"type":"LineString","coordinates":[[101.581,3.233],[101.577242,3.223395]]}}
  {"encoded_polyline":"<existing precision-5 route>"}
  {"route":{"geometry":"<precision-6 geometry>"},"geometry_format":"polyline6"}
  {"resolver":"osrm","points":[{"lat":3.1344,"lng":101.6869},{"lat":3.205,"lng":101.575}],"osrm":{"steps":true}}

OSRM options (inside payload.osrm):
  profile: <string> (default: operator OSRM_PROFILE or driving)
  alternatives: <boolean or integer 0-3>
  steps: <boolean>
  annotations: <boolean, CSV string, or array of nodes/distance/duration/
                datasources/weight/speed>
  exclude: <CSV string or array of profile-supported road classes>
  continue_straight: <boolean or default>
  snapping: [default, any]
  geometries: [geojson, polyline, polyline6] (default: geojson)
  radiuses: <one entry per location: nonnegative meters, unlimited, or null>
  bearings: <one [bearing,range] pair per location, or null; integer bearing
             0-360 and range 0-180>
  approaches: <one curb/unrestricted/null entry per location>
  hints: <one URL-safe base64 hint or null per location>
  generate_hints: <boolean> (default: false)
  skip_waypoints: <boolean>
  waypoints: <increasing stop-location indices including first and last;
              distinct from the top-level coordinate waypoints array>

Limits and usage:
  Local coordinate paths: up to 10,000 points.
  Encoded strings: up to 100,000 characters.
  OSRM requests: up to 100 input locations and 3 alternatives.
  Resolved routes: up to 50,000 points and 100,000 encoded characters.
  Road classes/profiles must be available on the operator's OSRM server.
  The default resolver is the public Project OSRM demo unless configured by the
    operator. Coordinates are sent to that server for road resolution.
  Resolve once, draw the returned geometry, and reuse {"route": resolved.routes[0]}
    for toll-rates, highways/inroute, and rsa/inroute to avoid repeat resolution.
  Operator routing configuration is not accepted as a caller-supplied server URL.
